# Video planning and scripting — proposal for review

Status: proposal only, revised 2026-10-03 after the founder’s coverage audit. All paths below are proposed unless described as existing. Kit files would ship under `template/`; runtime paths omit that prefix. No skills, scripts, media or UI are built by this proposal.

## 1. The system and its boundary

Copy the slideshow method: choose values from an anatomy, inherit the handle's defaults, select a sourced recipe, fill its beats, then approve the complete piece. Free writing fills the chosen slots; it does not decide the structure. The output is `pipeline/character/<video>/plan.json`, the existing character pipeline's sole planning input.

Coverage is the goal: an existing handle strategy or experiment selects the content. `video-fit` checks whether it can be executed and resolves its inputs; it must not redesign the handle, reassign topics, or discard a requested format because another format scores better.

Three story lanes are first-class: **pitch**, **discovery**, **everyday**, and **education**. Paid versus organic is a separate distribution choice. A discovery can be a pitch, but an everyday gym log need not contain a problem, an objection, an app name or a sales close. Product placement is independent of both story and filming format.

Planning stops at an approved, feasible plan. It makes no pictures, voices, keyframes, generation prompts or segments. Character definition remains `persona-identity` / `character-voice`; shots, storyboard gate A, spending approval, review and assembly remain production. Plan approval does not approve a storyboard or a generation. Posting and outcome collection remain outside both systems. Atlas is out of scope; it could read the §3 catalogues/observations, VIDEO-FIT mappings, draft/locked plans and approval digests without inventing another taxonomy.

## 2. Video anatomy: choose one value per slot

The taxonomy starts small. These are proposed controlled values, not claims that every combination wins. Each value carries evidence and capability status. Account role, persona and cadence are inherited from `ACCOUNTS.md` / `HANDLE.md`, rather than invented per video.

| Slot | Allowed values / rule |
|---|---|
| Objective | `reach`, `save_share`, `product_discovery`, `product_action`; one primary objective and its observable metric |
| Distribution | `organic`, `paid`; paid changes the eligible close, not the format |
| Story lane | `pitch`, `discovery`, `everyday`, `education` |
| Viewer moment / topic | One concrete situation and one subject, filled from product facts or cited research; these are text slots, not an expanding hook list |
| Filming format | `talking_head`, `hook_to_demo`, `live_use`, `before_after`, `text_over_action`, `voiceover_action`; `face_to_demo` becomes an alias of `hook_to_demo` (attention may be a face, cat or scene); capability restrictions below |
| Hook job | `discovery_regret`, `imminent_need`, `confession_reframe`, `quoted_challenge`, `specific_promise`, `peer_question`, `visible_result`, `in_progress`, `gratitude_discovery`, `category_analogy`, `withheld_reveal`, `explanation` |
| Hook channel | `spoken`, `visual`, `text`, `spoken_visual`, `text_visual`; `in_progress` permits no explicit hook sentence |
| Beat recipe | `pitch_proof`, `discovery_demo`, `routine_log`, `personal_note`, `state_change`, `explain_action`, `list_steps`, `setup_reveal`; defined below |
| Proof | `none`, `visible_action`, `real_screen_result`, `sourced_fact`; a numeric claim requires a fact reference |
| Product role | `absent`, `incidental_tool`, `story_solution`, `main_subject` |
| Name location | Set of `speech`, `overlay`, `caption`, `bio`, or empty; speech count `0` or `1` by default. A visible UI name is tracked separately |
| App screen presence | `none`, `incidental_use`, `demonstration`, `result`; any visible real app requires `app_insertion: true` |
| Product timing | `absent`, `opening`, `middle`, `closing`, `throughout`; converted to exact beat intervals, never left as a vague instruction |
| Viewer task on app beat | `read`, `recognise`, `believe`; exact screen id and hero string when reading is required |
| Close / CTA | `none`, `payoff`, `save`, `share`, `follow`, `question`, `profile`, `product_action`; one primary ask at most |
| Cast / framing | `human`, `mascot`, `none`; existing identity/version pins for generated cast. Visibility `face`, `hands_only`, `subject_only`. A real cat is a fixed subject or supplied clip subject, never an invented human narrator; mascot cast uses its own approved identity |
| Media origin / layout | Per beat `generated`, `supplied`, `mixed`; layout `sequence`, `split_screen`, `picture_in_picture`. Supplied includes own camera, permitted reference clips, real recordings and stills; source identity and provenance pinned |
| Series | `standalone`, `progress_log`; latter stores `{series_id,subject_ids,routine_id,episode,day,previous_plan_ref,state_fact_refs}` with evidence of actual progress |
| Hook framing | Optional `count`, `negative`, `audience_callout`, `lived_experience`, `professional_basis`; modifiers of a hook job, not additional hook families |
| World | Approved set ids and exact fixed-subject ids/count/size per beat; one outfit per generated human per video. Supplied scenes use source metadata rather than fictional set plates. Store shelves, carrier, bowls and two-cat scenes are explicit asset requirements |
| Length / canvas | Target `10`, `15`, `20`, `30`, `35–60` seconds; `9:16`. Bands are planning defaults, with a sourced exact duration allowed after feasibility review |
| Audio / text | Per beat `on_camera`, `voiceover`, `ambient`; narrator `character`, `supplied_speaker`, `original_synthetic`, `none`, with voice id and source. Overlay roles `hook`, `paragraph`, `step_label`, `comparison_label`, `day_counter`, `source_credit`, or none; exact timed text. Music is a publishing note only; the finished production file stays music-free |
| Experiment | `none`, `hook`, `proof`, `product_presence`, `close`, `cast`; one changed axis, an identified base and fixed remaining values |

**Recipes are ordered semantic beats, not shots.** Several beats can occupy one continuous production segment; a two-second hook does not require a two-second generation.

| Recipe | Ordered required beats | Lane / conditions |
|---|---|---|
| `pitch_proof` | call-out → problem/reframe → mechanism → proof answering one doubt → close | Pitch; mechanism and doubt filled from facts. Paid may end with product action |
| `discovery_demo` | attention → use/reveal → result | Discovery; gratitude, analogy, regret, quote and animal openings fill the same slots. A separate discovery sentence and closing payoff are optional; the app may be the last result |
| `routine_log` | task already underway → action → log/check → continue | Everyday; app optional, zero spoken app names and no CTA allowed |
| `personal_note` | admission → specific experience → what changed → reflection | Everyday or pitch; a product solution is optional, invented testimonials are forbidden |
| `state_change` | state/approach A → intervention/contrast → state/approach B → takeaway | Any lane; comparison mode `before_after`, `wrong_right`, `best_worst`; sequential or simultaneous layout, no unsupported causal claim |
| `explain_action` | observed sign/question → explanation → one action | Education; app absent or one incidental mid-video line/screen. Risk/health facts cite real sources |
| `list_steps` | specific promise → item/step ×n → takeaway | Education or discovery; repeat group has count/order, exact text and timing; one app may occupy a numbered item |
| `setup_reveal` | situation/tease → revealed message/result → optional response | Any lane; notification, forbidden reveal and product punchline use the same general reveal structure |

Each beat has one job, a time interval, exact words if any, a visible action, product visibility and a fact/evidence reference where needed. Hook records have named fill slots: discovery regret = `{familiar_activity, elapsed_time, discovery}`; imminent need = `{deadline, unfinished_job}`; confession = `{belief_or_habit, correction}`; quoted challenge = `{quote, response}`; promise = `{task, useful_result}`; peer question = `{shared_moment, question}`; visible result = `{before, after}`; in-progress = `{task, revealing_action}`. Additional hook slots: gratitude = `{person_role, useful_discovery}`; analogy = `{familiar_category, new_subject, shared_job}`; withheld reveal = `{audience, withheld_thing, payoff}`; explanation = `{observed_sign_or_question, meaning, action}`. “Everyone asks how I…” uses `specific_promise` plus an asked-for premise; a counter uses `in_progress`, and a warning uses `specific_promise` plus negative/risk framing. Do not invent elapsed years, results, credentials, requests or quotations to fill them.

**Compatibility rules.** Respect approved handle rules first. For organic pitch, delayed introduction and a payoff close are optional starter defaults, subordinate to the approved source strategy. “CatWise is the payoff” explicitly permits a closing product result; do not force an extra product-free beat. Do not apply “name the app once” to everyday videos. For discovery, early screen demonstration is an evidence-backed option, not an automatic violation: Potto and Stronger show the product around 2–6 seconds. An exception to an approved handle rule needs the user's explicit decision. Paid CTAs require a real destination; caption/bio placement must match the existing handle. A routine can show a real logging screen with zero verbal naming; it cannot show a fake generated UI. An app-free post must still fulfil the handle's topic and objective.

**Production capability is a separate gate.** Today P1 makes T talking segments without app insertion, and T / O / G / S / H / F / R / P with insertion. Existing face-to-demo production is usable; other modes need the shared bridge in §5. The revised design covers every video build inventoried in §6, while current code remains unchanged. Never call a design-covered type runnable until its bridge and assets exist, substitute generated footage for a requested real cat, or relabel silent action as talking to pass a check.

**Schemas** (schema version `1`; missing observations are `null`, not inferred):

- `video-patterns.json` / local `patterns.json`: `{schema_version, taxonomy_version, patterns[]}`. Each pattern: `{id, kind: hook|recipe|rule, definition, slots, allowed_formats, allowed_lanes, constraints, aliases[], evidence_ids[], scope, status: candidate|supported|contested|retired, capability: runnable|conditional|blocked, requires[]}`. Local records reference inbuilt ids and add scoped evidence/constraints; they do not redefine the id's meaning. New local candidates use `local:<slug>:<id>`.
- Observation: `{id, origin: inbuilt|competitor|niche|own, evidence_kind: observed|claimed|hypothesis|user_decision, source_ref, post_key, platform, app, handle, account_role, niche, language, posted_at, captured_at, sampling_method, attribution, kind, disposition, read_depth, anatomy, hook, beats[], metrics, limitations[]}`. `source_ref` contains portable source title/URL or relative asset path plus timestamp/section; not an expiring CDN link. `post_key` is platform + post id; null for a strategy decision/hypothesis, which instead has a stable source-section id. Planned cells never count as observed posts. `read_depth` is `cover|transcript|full_video`; `attribution` records whether promotion is verified, absent or unknown and why.
- `hook`: `{job_id, channel, spoken_verbatim, overlay_verbatim, first_frame_description, observed_until_s, confidence}`. Cover text, first-frame text and spoken words are distinct. `beats[]`: `{role, start_s, end_s, words, action, product_seen, app_named, screen_description}`. A cover-only read cannot establish demo timing or silence.
- `metrics`: `{views, likes, saves, shares, comments, snapshot_at, retention_source, hold_rate}`; unknown retention stays null. Aggregate evidence per matched scope stores `{n_posts, n_handles, n_apps, window, median_views, best_views, median_relative_to_handle, rates, selection_bias}`. Selected winners alone cannot supply an all-post median or a causal lift.
- Decision: `{date, finding_id, action: merge|candidate|reject|retire, target_id, reason, evidence_ids, taxonomy_version}`. The active catalogue stays compact; the raw evidence ledger may grow.

**Merge rule, run identically for B and C.** Deduplicate posts by `post_key` across batches and layers; retain multiple provenance links without counting the post twice. Classify manually from the observed opening and beat sequence; regex aliases are suggestions only. Match by hook job, slot structure and compatible recipe, not identical wording. A synonymous finding adds evidence to an existing id. A quote/example never becomes a new category.

A genuinely distinct pattern remains a candidate until seen in at least three fully read posts across two independent handles (a proposed curation threshold, not a statistical proof). Coordinated copies count as one operator/source where known. Cross-niche transfer requires observations in two niches; otherwise scope it locally. Unreadable, duplicate, off-niche and format/device confusions get a rejection reason. Production-unsupported but requested structures remain valid candidates with a capability gap; lack of implementation is not grounds to remove them from the anatomy. There is no automatic “append new hook” step. Start with twelve hook jobs and eight recipes; expanding them requires explaining the structural distinction and a taxonomy-version change. Keep at most three representative examples per pattern, replacing redundant examples with stronger evidence.

Read A → B/C → app/handle, as the slideshow path does. Explicit user decisions and production constraints bound selection. Relevant local evidence guides choices ahead of generic claims, but small samples stay experiments. Competitor and niche disagreement stays two scoped findings plus a proposed experiment; never average it into a universal rule. Show median, best, sample and caveats together. No points formula pretends that three copied clips outweigh a contradictory niche batch. Own outcomes can later enter the same merger through the existing `read` workflow; outcome collection is not a new planning stage.

**Inbuilt intelligence to distil from these files:**

- A subject doing the task can provide attention without a human face; a cat + real input/result can replace face→demo. Product payoff and one-use demonstration are separate from a compulsory CTA or app-free closing shot.
- Explanation earns an action: observation → meaning → one thing to do. Teaching, first-person experience and selling are distinct intents; explanation and how-to need no invented doubt, transformation or credential. A supplied expert and a fictional persona have different claim bases.
- Real demonstrations need real footage; precise pet counts, size, hands/props, source matching and longitudinal state belong in a plan. Lists, overlays, framing, comparison layout and series are independent slots, not new formats per topic.
- Repetition/median comparison is more informative than one outlier. Preserve source windows, baseline and sample count; the founder’s three-post reads and “high confidence” marks are user decisions, not universal evidence thresholds. The diagram’s one-source marker stays a limitation.
- Learned limits are scoped: the old question-to-app meme failed locally, the repaired feeling→app build is a new hypothesis; topic alone does not settle performance. CatWise’s 430/469/604 baselines, handle ownership, names, deadlines and local stop lists stay in local strategy, not the generic kit brain.

Store these as concise A rules/recipes with portable references, labelling observed findings versus founder decisions versus planned tests. Do not promote the strategy’s hypothetical clinical numbers or the diagram’s planned experiments into winning evidence.
